# 书口 · 把「厚度」还给电子书

一个**单文件**交互原型（`index.html`，含内联的 PDF 解析器），用来验证一个命题：

> 纸质书和电子书的差别，不在于"能不能翻页"，而在于**位置是不是一个可被抓取的连续量**。

直接双击 `index.html` 打开（纯本地，无依赖、无网络请求）。

---

## 摊开的一本书

界面是一本摊开的书：**左页（verso）— 书脊 — 右页（recto）**，翻动的最小单位是**一张纸**（1 张 = 2 页 = 1 个跨页）。

```
[左侧已读纸堆]  [左页]  书脊  [右页]  [右侧未读纸堆]
     ↑ 越来越厚                              ↑ 越来越薄
```

**左厚 + 右厚 + 摊开的 2 页 ≡ 常数**。整块书体宽度永远不变，只有摊开的位置在块内向右漂移。

---

## 三个核心机制

### 1. 厚度按内容分带，且可以直接点选

书口不是一叠均质的纸，而是按章节真实页数分段的——**带越宽，那一章页数越多**。
同一章被摊开位置切开时，会**同时出现在左右两侧**：左边是已读的那段，右边是没读的那段。

**单击书口上的任意一段章带就跳到那一章**（可前可后）；悬停会高亮该带并显示章名。
侧栏「章节厚度地图」的每个条目也能点。

### 2. 增益由拇指速度主导

```
增益(张/像素) = 0.020 + (0.460 − 0.020) × max(w_速度, w_距离 × 0.55)
```

- **慢慢捻** → `0.020 张/px`（50px 一张跨页），能精确停在某一个跨页上
- **快速扇** → `0.460 张/px`，一划就是一叠，能直接跨章

速度是主信号，累计距离只作次信号且**封顶 55%**——否则任何一次长距离慢拖都会退化成粗档。滚轮同一套逻辑（慢滚 1×、快滚 5×）。

### 3. 双向翻页有六条路径

| 操作 | 效果 |
|---|---|
| 左右书口上下拖 | 向上 = 前进，向下 = 后退 |
| 单击书口章带 | 跳到那一章，**可前可后** |
| 点击左页 / 右页 | 后退 / 前进一张 |
| `←` `→` `↑` `↓` `空格` | 翻一张 |
| 侧栏「← 上一张 / 下一张 →」 | 翻一张 |
| 滚轮上下 | 后退 / 前进，快滚加速 |

翻页动画是真正的绕书脊翻纸；快速翻动时纸片从书口抬起、**向左掠过右页**，每一片都是从真实页面渲染结果压缩采样来的切片。

## 放大：整本书一起变大

有些文档的字天生就小，所以整个书体（页、书脊、两侧书口厚度）可以一起缩放，`50%`–`500%`：

- **常驻悬浮条**右上角 `−` / 百分比 / `＋`；`Ctrl` + 滚轮、`Ctrl` + `=`/`-`/`0` 同样有效，**触控双指捏合**也可以
- 缩放**以光标（或双指中点）为锚**：锚点下的那一点内容保持不动，而不是傻居中
- 百分比读数点一下就回到「适应窗口」并重新居中

放大到超出视口后，**按住页面拖动 = 平移**；而「轻点左页后退 / 点右页前进」仍然保留（靠 7px / 500ms 的阈值区分拖动与轻点）。

关键点是**放大后的字必须是重新栅格化的，不能是位图拉伸**。`paintPage` 本身与分辨率无关（一切都按 `W`、`H` 比例算），所以只要按放大后的目标尺寸重画一遍，字就自然是锐的。为此：

- 页面比视口小 → 走整页高清缓存（静止时零重画）
- 页面比视口大 → 只渲染**视口覆盖到的那一块**，仍然按整页坐标绘制、平移进画布。因为 5× 时一页的整页位图是 **25.8M 像素 ≈ 98MB**，缓存几张就爆内存
- 高清缓存改为按**像素总量**（而非条目数）淘汰，总预算 18M 像素 ≈ 72MB
- 完全落在视口外的页面直接跳过，不再退回低清路径白画一张巨大位图

## 隐藏顶栏 / 侧栏

顶栏和侧边面板都可以收起来，把整块屏幕让给书：右上角悬浮条的「顶栏」「侧栏」按钮，或键盘 `T` / `P`。

两个面板都隐藏时画布**正好铺满窗口**，且会立刻按新尺寸重排（页更大、重新居中）。

**悬浮条是刻意常驻的**：顶栏一旦隐藏，放在顶栏里的入口就再也点不回来了，所以缩放与显隐的入口必须挂在画布上、且不被书页遮住（实测 `elementFromPoint` 命中按钮本体）。网格的行列都是显式定位的，隐藏只压掉对应的轨道，所以宽屏双栏与窄屏单栏两种布局都成立。

## 导入自己的文档

点右上角「导入文档」，或直接把文件拖进窗口。

| 格式 | 解析方式 |
|---|---|
| **Markdown** | 完整块级 + 行内解析，**按 Markdown 预览格式排版**（见下） |
| **EPUB** | ZIP 解压（浏览器内置 `DecompressionStream`）→ OPF → EPUB3 nav / EPUB2 NCX 目录 |
| **PDF** | 自带解析器：有文本层就提文本 + **PDF 目录分章**；**扫描件（无文本层）自动转「图像页模式」** |
| **TXT** | `第 N 章/回/节/卷/篇`、`Chapter N`、独立成行的编号标题 |
| **HTML** | 取块级元素为段落，`h1~h6` 切章并保留样式 |

### Markdown 按预览格式渲染

不是把 `#` 和 `*` 当纯字面量读，而是真正排版：

- **块级**：`#`~`######` 标题（1~3 级切章，4~6 级在正文内放大加粗）、段落、`-`/`1.` 列表（带项目符号与悬挂缩进）、`>` 引用（左侧竖线 + 淡字色）、``` 围栏代码块（底色 + 左侧色条 + 等宽字体）、`---` 分隔线、表格行
- **行内**：`**粗体**`、`*斜体*`、`***粗斜***`、`` `行内代码` ``、`[文字](url)`（保留文字、丢弃 URL）、`![图](src)`（降级为 `［图：说明］` 占位，不联网加载）、反斜杠转义
- `snake_case` 这类下划线不会被误判成斜体（要求两侧是词边界）
- 段落续行拼接时，中日韩之间不补空格

### PDF 支持

自带一个零依赖的 PDF 文本与目录提取器（内联在 `index.html` 里，同时保留源文件 `pdf.js`）：

- **目录分章**：`/Outlines` → `/First` → `/Next`（递归深度 3，防 `/Parent` 环），`/Dest` 数组或名字、`/A << /S /GoTo >>`、`/Names /Dests` 名字树；目标解析成页序号后，按「本条目页 → 下一条目页」切章
- **无目录时的兜底**：在正文里找章节样式的行（`第 N 章` / `Chapter N` / `1.2 标题`）；再不行就按每 8 页分节
- **文本提取**：`ToUnicode` CMap（`bfchar`/`bfrange` 含数组形式）、Type0/Identity-H 双字节、简单字体 WinAnsi/MacRoman/Standard + `/Differences` 字形名表；**没有 ToUnicode 时**对 `GBK-EUC-H`/`UniGB-UCS2-H`/Big5/EUC-JP/EUC-KR 等预定义 CJK CMap 用 `TextDecoder` 直接解码（中文发票、火车票就是这类）
- **结构**：经典 xref 表 + `/Prev` 增量更新、PDF 1.5+ 交叉引用流（`/W` `/Index`，含混合 `/XRefStm`）、`/ObjStm` 对象流、坏 xref 时按 `N G obj` 字节扫描兜底
- **过滤器**：Flate / ASCIIHex / ASCII85 / RunLength，含 PNG 与 TIFF Predictor
- **不支持**：加密 PDF（明确报错）、LZWDecode、无 ToUnicode 且无法识别的子集字体（输出空串而非乱码）
- 「导入文档」的**文件选择器也已接受 `.pdf`**（原先只写了 txt/md/html/epub，PDF 只能靠拖入触发）

### LaTeX / pandoc 排版（`cm` 坐标 · 词距 · 命名目标）

`md → pdf`（pandoc + LaTeX，经 pypdf 落盘）这一类 PDF 的排布方式与普通「文本流」PDF 完全不同，
一碰就散。用真实文档 `hello-algo_1.2.0_zh_rust.pdf` 复现出来的三个症状是：
**387 页被读成 1066 页 / 104 条目录全丢 / 代码里的空格全部消失**。
三处根因其实是同一件事：**把二维绝对定位当成了一维文本流**。

- **文本坐标必须乘 CTM**。这类文件每页开头是 `q 1 0 0 1 72 720 cm`，文字再 `BT ... Td` 摆进去。
  不跟踪 `cm`/`q`/`Q` 的话所有 Y 都是负值（`-225`、`-537`），整页文字等于跑到纸外。
  现在按「文本矩阵 × CTM」求页面真实坐标，并用 `q`/`Q` 存还图形状态。
- **词距与缩进是「位置」，不是空格字符**。代码块尤其明显：
  ```
  BT /F5 9.9626 Tf 13.81 -26.453 Td[<f357f35b000ff357>...]TJ ET
  BT /F5 9.9626 Tf 84.537 -26.453 Td[<000f>...]TJ ET      ← 84.5 是缩进
  BT /F5 9.9626 Tf 183.258 0 Td[...]TJ                    ← 183 是词间空隙
  ```
  现在按「上一段结束 X → 本段起始 X」的空隙反推空格数，缩进则**按版心还原**：
  版心取「行首 X 的众数」而不是最小值（整页都是代码时，代码块左缘才是版心），
  并且要求至少两行落在同一个 X 上才认定版心存在，避免单行页面被凭空顶开。
- **目录目标是字符串形式的命名目标**：`/A << /S /GoTo /D (chapter\052\0562) >>`。
  只认 `/Dest` 数组和 `PDF_Name` 会让这类目录**整份丢失**；现在也接受 `PDF_String`，
  解码后去名字树里查。另外 `buildOutline` 现在会自己补建「页对象号 → 序号」映射，
  不再依赖调用方先建好。

空格阈值不是拍出来的：这份文档的词间空隙实测呈**双峰** —— 代码页的紧邻词距约 0.3 em、
正文页词距集中在 1.5 em，两者之间几乎为空。所以 `0.25~2.0 em` 统一给 **1 个空格**，
更大的空隙按分栏/表格对齐封顶；既不漏掉紧词距，也不会把 1.5 em 放大成两三个空格。
文字推进宽度一律**取偏小的系数**（半角 0.45 / 等宽 0.55 / 全角 0.95 em）：
估宽一旦越过下一段起点，空隙就会被算成 0，`let mut` 会拼成 `letmut` —— 这个坑踩过一次。

**仍然没做的**：代码高亮、公式的数学排版（`𝑂(1)` 这类按 Unicode 数学字符原样输出）、
表格的列对齐（会被重排成连续文本）。

### PDF 原版页面渲染（Koodo 式）

PDF 导入的主路径改为**原版页面模式**：解析只做两件事——元数据（标题/页数）与章节目录，
每一页按原始版面交给内嵌的 Mozilla pdf.js 渲染成位图。文字排版、内嵌图、代码缩进天然原样，
不再有「重排走样」这一类问题。

- 页面描述符 `{kind:"pdfjs", page:n}` 与扫描页共用同一套图像页管线（缓存/防风暴闸门/放大补清晰度）
- 区别在解码方式：扫描页解文件里嵌的位图，pdfjs 页按目标分辨率**重新栅格化**——矢量页放大依然锐利，
  所以 `imgTargetFor` 对它不做原图长边封顶
- 渲染**串行队列**：并发渲染多页会瞬间吃掉几百 MB
- 旧的文本重排路线保留为 fallback（渲染内核意外失败且有文本层时自动降级，状态栏会标注）
- 无目录时按每 20 页分节兜底；目录条目过多按层级抽样到 ≤40 条

主程序块（书口 UI）曾因脚本事故丢失，已依据三套回归测试的契约重建，
源码分片在 `main-0*.js`，用 `node inject-main.js` 注入 index.html（带语法检查与块身份校验）。

### 正文页的内嵌插图也能显示（③b）

`hello-algo` 这类 LaTeX/pandoc 产物的页面是「上面正文、中间一张示意图」，整页降级成图像模式
会丢掉可选择、可搜索的文字，所以文本模式里多了一条**按位置画内嵌图**的路径：

- **`/Indexed` 调色板颜色空间**：`[ /Indexed /DeviceRGB hival <lookup> ]`（hex 字符串与流引用两种形式）
  按 `lookup` 里的 `(hival+1)×基色分量` 字节展开成 RGB —— 482 张示意图全靠它
- **`/SMask` 软掩码**：带透明通道的图合成成 RGBA（`comps=4`），黑背景变透明而不是黑块压住正文；
  绘制时先铺白底再贴图（纸张渐变不会透上来弄脏图）
- **位置回传**：`pdfExtract(buf, {withImages:true})` 的每页多带
  `images: [{line, charInLine, info}]` —— `line` 是画这张图时已输出的文本行数，
  `charInLine` 是行内偏移（`Do` 执行时当前行还在缓冲里，所以「第一行文字之后的图」是 `line=0, charInLine=首行长度`）
- **交错进正文**：每页按图出现的位置把图插在段落之间；一个插图占 `FIG_LINES=8` 行高
  （占 1 行会被压成一条缝），分页时整块图放不下就推到下一页，绝不会被页界切成两半
- 解码与扫描页共用同一套缓存 / 防风暴闸门 / 超时重试，占位框先画出来避免正文跳动

### 扫描件也能导入（图像页模式）

没有文本层的 PDF 不再报错了。扫描件每一页本质上就是一张嵌入图片，所以**一页 PDF = 一页书**：

- **DCTDecode（JPEG）** — 这是扫描件最常见的编码，直接取出原始字节交给浏览器解码，不需要任何图像解码器
- **FlateDecode + 8bpc 的 DeviceRGB / DeviceGray / DeviceCMYK** — 解出原始位图包成 `ImageData`
- 提取时会把 `DCTDecode` 之前的 ASCII85/Flate 等过滤器先解掉，所以「ASCII85 + DCTDecode」这类组合也能用
- 章节照旧**按 PDF 目录分**（扫描书往往带完整书签）；目录条目过多会自动抽样，否则 205 条目录压在 241 页上、每段不到 1 像素既看不见也点不中
- 图像页模式下不再强行凑偶数页数（否则 1 页的章会被撑成 2 页），只保证总页数为偶数

**内存约束**：绝不预解码整本书（241 页 × 2144×3024 会吃掉几个 GB）。
只解码当前看得见的几页，解码完立刻缩到目标尺寸再缓存；缓存按**像素总量**（26M px ≈ 104MB）而不是页数淘汰。
解码超时会释放「进行中」标记让下一次重画重试——否则一次偶发失败会让这一页永久停在占位状态。

**解码分辨率跟着缩放走**：固定在 900px 时，3× 放大等于把 900px 的图撑到 2550 设备像素，扫描件的小字照样糊。
所以解码目标 = 页面在屏幕上的设备像素宽度，夹在 `[900, 2400]`，但**绝不超过原图长边**；
放大后旧图继续显示、后台补一张更清晰的（不会闪回「正在解码图像…」）。

这里有两道防「解码风暴」的闸，都是踩过坑加的：目标必须被**原图长边**封顶（廉价扫描只有 1200px 时，
否则永远追不上目标、每帧重解一遍同样的图）；比较必须用**长边**（解码是「长边缩到目标」，
竖版页用短边去比长边目标会永远显得不够，同样每帧重解）。

**不支持**：CCITTFax / JBIG2 / JPX 这类传真与 JPEG2000 编码需要专门解码器，会明确标注为「编码不支持」而不是静默失败。
另外本模式不做 OCR —— 扫描件里的文字是图，不能被选中或搜索。

### 导入后的统一处理

不管来源是什么，都走同一条管线：**块序列 → 分页固化**。
分页固化保证**每章独占整数页、且页数为偶数**——否则会出现一个跨页横跨两章，把书口的分带切断。

排版要点：换行引擎用「全角 = 1、拉丁 = 0.55、等宽 = 0.62」的同一套预算，所以换行与分辨率无关、可复现；
字号同时受**版心宽度**与**行高**约束（`min(版心/字数×0.95, 行高×0.92)`），否则长行会被页面右缘整片裁掉。

**渲染分辨率**：正文页按屏幕分辨率（`pageW×DPR`）单独渲染并缓存，
低清的 196×280 缩略图只留给翻页扇形的纸片切片——那里模糊反而像运动模糊。
（曾经图省事让正文也用那张缩略图，等于拿 6px 的字撑 14px，整页发糊。）
快速翻动时每帧只补 1 页高清，静止时一次补齐两页，避免掉帧。
放大到页面超过视口时，改成只渲染视口那一块（见「放大」一节），否则单页位图会到 98MB 量级。

### 改完 `pdf.js` 必须重新内联

`index.html` 是单文件交付物，`pdf.js` 是它内部那段解析器的**可读源码**，两者是同一份代码的两份拷贝。
改完 `pdf.js` 一定要跑一次：

```bash
node inline-pdf.js     # 把 pdf.js 重新内联进 index.html 的第一个 <script> 块
```

否则会出现「改了源码、页面行为却完全没变」的假修复（这次就踩过：改完 `pdf.js` 直接去浏览器验证，
结果读出来还是旧行为）。`test-logic.js` 现在会把 index.html 的**两个 script 块都跑一遍**，
所以「改了没内联」和「内联了但两份不一致」都能被测试抓到。

## 对照模式

右上角可切换 **普通电子书**：书口被替换成一根进度条，拖拽固定 `1 : 104px`。
同样拖动 600 像素：纸书模式翻过 100+ 张跨页，普通电子书只翻 6 张。跨过全书需要拖动约 16600 像素——物理上做不到。

## 明确没做的

- **不用进度条替代厚度**，也不让两者并列——进度条是抽象的，厚度是具体的。
- **不做拟物美化**。动画再漂亮，只要拖动还是 1:1、位置还是百分比，厚度感就不会出现。
- **不做真物理模拟**。参数化曲面即可拿到 90% 观感。
- **PDF 现在跟踪 CTM**（文本坐标会乘 CTM 并随 `q`/`Q` 存还），但阅读顺序仍是内容流绘制顺序，
  表格类 PDF 的单元格会按绘制顺序串行输出（发票可读但不是视觉顺序）。
- **插图位置是近似交错**：图插在哪两段之间按「块字数比例 ↔ 行号」折算（`pdfTextToBlocks` 已把行并成段落，
  没有保留行号映射），绝大多数示意图落在正确段落旁边，但个别可能偏一段。
- **PDF 不处理加密、不做 OCR、不支持 LZWDecode**。
- **扫描件不 OCR**：图像页模式只把扫描页当图显示，文字不可选中、不可搜索；传真类编码（CCITTFax/JBIG2）也没有解码器。
- **放大不重排文字**：每页仍是 23 行 × 24 字，放大只改变呈现，**分页、章节页数、书口厚度一概不变**——书的结构不该因为看得更清楚而改变。
- **平移没有惯性**，松手即停（1:1 跟手）；缩放也不持久化，刷新回到 100%。
- **扫描件放大后的清晰度有上限**：受解码目标 `[900, 2400]` 与原图分辨率双重限制，且已解码的页不会重新解码（避免拖动时反复解码），所以扫描件在 3× 以上仍可能偏软。
- **捏合缩放只在触控下生效**（用合成 PointerEvent 测过数学部分，没有在真实触摸屏上试过）。

## 什么时候选择放大、什么时候选择隐藏面板

- 字太小 → `Ctrl` + 滚轮（或双指捏合）以光标为锚放大，再按住页面拖到想读的位置
- 屏幕小或只想读 → `P` 收起侧栏、`T` 收起顶栏，画布铺满窗口，版面自动变大一档
- 放大到 3× 以上时侧栏的「章节厚度地图」依然可用（它不在画布上），但书口大部分会移出视口——此时点章带比拖书口更省事
